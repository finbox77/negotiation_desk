# Стол переговоров — отдельное приложение (PWA)

Рабочее окно сделки Simonix, вынесенное из сайта в самостоятельную программу:
список столов, лента сообщений, участники, документы-вложения, допуски и
сигналы «клиент / свои». Приложение можно установить на телефон или компьютер
и открыть без адресной строки, а работать оно умеет в двух режимах:

| Режим | Что нужно | Данные |
|---|---|---|
| **Демо** (по умолчанию) | только `npm install` | вымышленные столы внутри браузера, можно писать и менять допуск |
| **Сайт** | запущенный Simonix на `localhost:3000` + вход | настоящие `negotiating_table`, `negotiation_messages`, `negotiation_participants` |

Демо-режим существует, чтобы приложение запускалось **без всего проекта** —
одна папка, одна команда, живой стол через две секунды. Режим «Сайт» —
это та же логика, но через API основного репозитория.

---

## 1. Быстрый старт в VS Code

### Вариант А — открыть только приложение (рекомендуется для работы над столом)

```bash
cd apps/negotiation-desk     # из корня репозитория
npm install
npm run dev
```

Открыть <http://localhost:5174>. Всё. Основной сайт, база и `.env` не нужны.

В VS Code: **File → Open Folder… → `apps/negotiation-desk`** (или
`code apps/negotiation-desk`). Тогда терминал сразу открывается в нужной папке,
а поиск и «Go to definition» не бегают по всему монорепозиторию.

### Вариант Б — из корня репозитория

В корне добавлены короткие команды:

```bash
npm run desk:install   # один раз
npm run desk:dev       # http://localhost:5174
```

Остальные: `npm run desk:build`, `npm run desk:preview`.

> Требуется Node 20.19+ (Vite 7). Проверено на Node 22.

## 2. Режим «Сайт»: связать с основным проектом

1. В корне репозитория запустить сайт:

   ```bash
   npm run dev          # http://localhost:3000, memory-режим без базы
   ```

2. Войти на сайте: <http://localhost:3000/auth/login>
   (демо-аккаунты — `director@simonix.dev` / `director123` и другие из README).

3. В приложении открыть **Настройки → Источник данных → Сайт** и нажать
   **Применить**. Адрес API оставить пустым: Vite проксирует `/api` на
   `localhost:3000` (см. `vite.config.ts`).

4. «Проверить связь» покажет число доступных столов и имя пользователя.

### Почему не нужен токен и CORS

Браузер обращается к `localhost:5174`, Vite пересылает `/api/**` на
`localhost:3000`. Cookie-сессия `simonix_session` привязана к хосту, а не к
порту, поэтому браузер сам отдаёт её прокси, а прокси — сайту. Никаких
`Authorization`-заголовков и настройки CORS на этом этапе нет.

Если указать в настройках абсолютный адрес (`http://localhost:3000`), браузер
пойдёт напрямую: это сработает только при отключённой проверке origin, поэтому
для разработки оставляйте поле пустым.

### Телефон в той же Wi-Fi

Оба сервера слушают `0.0.0.0`. На телефоне:

- демо: `http://<IP-компьютера>:5174`;
- сайт: войти на `http://<IP-компьютера>:3000/auth/login`, затем открыть
  `http://<IP-компьютера>:5174` — cookie уже будет у хоста.

Установка PWA на телефон требует HTTPS (или `localhost`): по обычному
`http://192.168…` браузер не включит service worker. Для теста установки
используйте `npm run build && npm run preview` на компьютере и `localhost`.

## 3. Сборка и установка

```bash
npm run build      # tsc --noEmit && vite build → dist/
npm run preview    # раздача dist на http://localhost:5174
```

`dist/` — статика: `index.html`, JS/CSS, manifest, service worker, иконки.
Её можно положить на nginx в корень домена или в подпапку `/desk/` — сборка
использует относительные пути (`base: './'`).

Признаки установки: Chrome/Edge показывают иконку установки в адресной строке,
в настройках приложения появляется кнопка **«Установить приложение»**.
iPhone/iPad: «Поделиться» → «На экран Домой» (Safari не присылает
`beforeinstallprompt`, поэтому кнопки нет — есть подсказка).

Service worker кеширует **только оболочку**. `/api/**` всегда идёт в сеть:
сообщения и допуски нельзя показывать из устаревшего кеша. После изменения
оболочки поднимите `VERSION` в `public/sw.js`.

## 4. Что внутри

```
apps/negotiation-desk/
├─ index.html                  метатеги PWA, подключение manifest
├─ vite.config.ts              порт 5174, прокси /api, allowedHosts
├─ public/
│  ├─ manifest.webmanifest     имя, иконки, standalone
│  ├─ sw.js                    кеш оболочки, /api — только сеть
│  └─ icons/                   192/512/maskable + apple-touch
└─ src/
   ├─ App.tsx                  каркас, баннеры, мобильные панели
   ├─ styles.css               дизайн-токены Simonix, светлая/тёмная тема
   ├─ desk/
   │  ├─ types.ts              ★ контракт с сайтом (единственная точка стыковки)
   │  ├─ api.ts                HTTP-клиент + нормализация snake_case → camelCase
   │  ├─ demo.ts               демо-столы, три профиля допуска
   │  ├─ useDesk.ts            состояние: снимок, открытый стол, отправка, seen
   │  ├─ config.ts             .env и адреса по умолчанию
   │  ├─ labels.ts, format.ts  русские подписи и даты
   │  └─ useInstallPrompt.ts   beforeinstallprompt
   └─ components/              TopBar, TableList, ChatView, MessageItem,
                               Composer, ContextPanel, SettingsDialog, Icons
```

Ключевое решение: **приложение не импортирует код сайта**. Общая часть —
только HTTP-контракт и дизайн-токены. Поэтому папку можно целиком скопировать
в отдельный репозиторий, и она продолжит собираться.

## 5. API, который использует приложение

Все маршруты — в основном репозитории, с обычной сессией Simonix.

| Метод | Путь | Что отдаёт |
|---|---|---|
| `GET` | `/api/v1/negotiations` | снимок стола: viewer + список окон + итоги |
| `GET` | `/api/v1/negotiations/:id` | карточка окна: стол, участники, контекст |
| `GET` | `/api/v1/negotiations/:id/messages` | сообщения с учётом допуска |
| `POST` | `/api/v1/negotiations/:id/messages` | отправить сообщение |

Снимок (`GET /api/v1/negotiations`) — camelCase, даты ISO:

```json
{
  "viewer": { "id": "u…", "name": "Анна Смирнова", "clearanceLevel": 1, "companyId": "c…" },
  "tables": [
    {
      "id": "nt…",
      "title": "Лизинг ATLAS-6 (2 шт.)",
      "disputeType": "pre_contract",
      "status": "open",
      "statusLabel": "открыт",
      "dealId": null,
      "productId": "pr…",
      "environmentId": "env…",
      "participants": 4,
      "messages": 5,
      "fresh": 2,
      "signal": "client",
      "last": {
        "id": "nm…",
        "author": "Наталья Гордеева",
        "text": "Пришлите финальную смету…",
        "createdAt": "2026-10-20T09:12:00.000Z",
        "fresh": true
      },
      "createdAt": "2026-10-12T09:00:00.000Z",
      "updatedAt": "2026-10-20T09:12:00.000Z"
    }
  ],
  "totals": { "tables": 1, "fresh": 2, "freshFromClients": 2, "signal": "client" }
}
```

Правила, которые нельзя терять при переносе:

- **Свежесть** — сообщения не от смотрящего за последние 72 часа.
- **Сигнал**: `client` — автор из чужой компании с типом `client`; `team` — свои
  и партнёры; `none` — нового нет.
- **Допуск**: сообщение видно, если `viewer.clearanceLevel <= required_clearance`.
  Нельзя отправить сообщение с допуском меньше своего.
- **Доступ к столу** — только инициатор и участники; иначе 403.

Ответ `GET /api/v1/negotiations/:id/messages` — существующий формат сайта
(snake_case), приложение нормализует его в `src/desk/api.ts`. Отправка:

```json
POST /api/v1/negotiations/nt…/messages
{ "text": "Принято", "required_clearance": 3, "files": null }
→ 201 { "ok": true, "id": "nm…" }
```

## 6. Что уже работает

- список столов, поиск, выборка фильтров («≡» перед «Все»: Все, Новые,
  Созданные мной, Клиенты, Партнёры и по статусам; чипсы прокручиваются и
  убираются крестиками);
- **закрепление окон**: одинарный клик по чату — предпросмотр в центре,
  двойной клик или отправка сообщения — закрепление в мини-шапке (новые
  закрепления появляются слева, старые сдвигаются направо);
- **мини-шапка**: вкладки закреплённых окон фиксированной высоты, зелёный
  полый кружок у непрочитанных, подсказка полного названия при наведении,
  «≡» с краю — рулетка всех открытых окон со скроллом;
- **статусы чата** («≡» рядом с обновлением): открыть, ожидание, в работе,
  вопрос решён, закрыть (в закрытом чате отправка недоступна); отдельно —
  «Удалить» с вводом пароля (пока пароль по умолчанию «admin» — введён и виден);
- сигналы и счётчики непрочитанного (локальные отметки в `localStorage`,
  отдельно для демо и для сайта; серверная таблица прочтений — следующий этап);
- лента: текст, файлы, системные события, звонки, чипы допуска;
- **вложения**: «Загрузить с устройства» (файлы уходят с сообщением),
  «Из кабинета» — заготовка под документы основного проекта;
- **сохранение чата в Word**: тема, участники, переписка, время и вес —
  документом на устройство; рядом создаётся папка файлов чата (до 10 МБ);
- **личные чаты и новые темы**: «Написать» по участнику, «+» в списке столов
  с модалкой добавления людей в новый чат;
- **участники**: уровень допуска, тонкий статус-ободок аватара (зелёный — в
  столе, серый — не в столе), контекстное меню (написать, подсветить
  сообщения, счётчик сообщений, очистка истории с выбором числа последних,
  удалить из чата);
- **перенос участника**: drag-and-drop из правой колонки на вкладку окна или
  прямо в центральное окно — участник привязывается к чату;
- **дерево участников и окон**: плавающее окно, слева окна, справа участники
  (сущности не дублируются); выбор окна подсвечивает его участников, выбор
  участника — его окна; привязка к чатам списком по галочке; двойной клик по
  окну — открыть его на столе; поиск по именам и тексту сообщений;
- **окна участника**: клик по имени — снизу все его чаты и переданные файлы
  (список сворачивается);
- интерактивная эмблемка: точка зеленеет, пока есть непрочитанные окна;
- правая колонка: зритель, участники, продукт, объект, сделка;
- настройки: демо/сайт, профиль допуска, адреса, тема, установка PWA;
- мобильная раскладка: список ↔ лента, safe-area, установка на экран.

Чего пока нет (осознанно):

- загрузка бинарных файлов на сервер: имена файлов уходят в `files`, а
  «Из кабинета» (документы `d_*`) и серверное хранение вложений — после
  подключения к основному проекту;
- realtime: обновление по кнопке, без polling/SSE;
- серверные отметки о прочтении и push-уведомления;
- звонки (события отображаются, инициировать нельзя);
- офлайн-запись: при отсутствии сети показывается баннер, сообщения не встают в очередь.

Локальный слой (`src/desk/local.ts`) хранит в браузере новые окна-чаты,
привязки участников, очищенную историю и личные переписки — точки стыковки
с API помечены комментариями `SYNC`.

## 7. Как вынести в отдельный репозиторий

1. Создать пустой репозиторий, например `simonix-desk`.
2. Скопировать **содержимое** `apps/negotiation-desk` в корень нового репозитория
   (не саму папку).
3. В новом репозитории: `npm install && npm run dev`.
4. Backend-маршруты `src/app/api/v1/negotiations/**` и функции
   `getNegotiationDeskSnapshot` / `getNegotiationCard` остаются в репозитории
   сайта — отдельное приложение не тянет за собой базу.
5. В новом репозитории зафиксировать контракт: `src/desk/types.ts` +
   раздел 5 этого README. При изменении API обновлять обе стороны.
6. В корневом репозитории оставить папку `apps/negotiation-desk` как встроенную
   копию (или заменить её git-submodule — решать при выделении).

Никаких миграций для стола не нужно: используются таблицы `006`/`010`
(`negotiating_table`, `negotiation_participants`, `negotiation_messages` и
связующие).

## 8. Как встроить обратно в кабинет

Самый дешёвый путь — оставить PWA отдельной страницей:

- собрать `dist/` и положить в `public/desk/` основного сайта;
- из кабинета открывать `/desk/` в новой вкладке или iframe;
- на том же домене cookie-сессия общая, `apiBase` оставить пустым.

Более глубокая интеграция (компоненты внутри Next) потребует:

- перенести `src/components` и `src/desk` в `packages/desk-ui`;
- заменить `import.meta.env` в `config.ts` на пропсы/`process.env`;
- заменить `styles.css` на токены кабинета (классы уже совпадают по смыслу);
- оставить `api.ts` как есть — он не зависит от Vite.

Рекомендация: сначала довести PWA и контракт, потом решать про встраивание.
Пока приложение живёт в `apps/`, встроить его обратно можно в любой момент без
переписывания данных.

## 9. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `401 Требуется вход` | не выполнен вход на сайте или истекла сессия. Войти на `/auth/login`, затем «Проверить снова». |
| `Нет связи с сайтом` | не запущен `npm run dev` в корне, либо изменён `DESK_API_PROXY`. |
| Пустой список в режиме «Сайт» | у пользователя нет столов, либо таблицы `006/010` не применены к базе. |
| CORS-ошибка | в настройках указан абсолютный `apiBase` на другой origin. Очистить поле — пойдёт через прокси. |
| Порт 5174 занят | поменять `server.port` в `vite.config.ts` (и `preview.port`). |
| Установка PWA не предлагается | нужен HTTPS или `localhost`, production-сборка и service worker. Выполнить `npm run build && npm run preview`. |
| После обновления старая версия | поднять `VERSION` в `public/sw.js`, перезагрузить с очисткой кеша. |
| Корневой `npm run build` ругается на приложение | `apps` исключён из корневого `tsconfig.json`; собирать отдельно `npm run desk:build`. |
